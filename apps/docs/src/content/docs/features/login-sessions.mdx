每次登录都会在服务端建一个会话：谁在哪台设备上登着、多久没操作、还能用多久，都看得到，也能随时让它下线。网页、桌面、手机三端各有一套时长和设备数上限，在参数配置里改。

本页先讲怎么查看和踢掉一个会话，再讲一个会话从登录到结束会在哪些地方被结束、对方会看到什么提示，最后是常见问题。

## 查看与结束会话

**入口：**「系统监控 → 在线用户」（`/monitor/online`）。只有**超级管理员**能查询会话和强制下线；给普通角色授予菜单，不会同时获得这些接口的权限。

1. 按用户、登录端、IP、浏览器和登录时间找到目标会话。
2. 核对最后活跃时间、实时连接状态和剩余有效期，确认是要处理的设备。
3. 对目标会话执行「强制下线」。

**看到什么算成功：** 有实时连接的页面立即回到登录页并显示原因；没有实时连接时，下次请求会收到带原因的 401。同一浏览器中，一个标签页退出后，其他标签页也会退出。

## 时长与设备上限

每次登录在服务端建一个会话，会话 ID 从登录到退出不变。登录时客户端说明自己是哪一端，三端各用一套规则：

<div className="doc-table-scroll" role="region" aria-label="会话规则对照" tabIndex={0}>

| 规则 | 网页端 | 桌面端 | 移动端 |
|---|---|---|---|
| 空闲超时 | 120 分钟 | 120 分钟 | 30 天 |
| 最长登录（从登录那一刻算，一直在用也不延长） | 7 天 | 7 天 | 90 天 |
| 同一账号在这一端的会话上限 | 不限 | 不限 | 1 |
| 超过上限时 | 挤掉最久没活跃的 | 挤掉最久没活跃的 | 挤掉最久没活跃的 |

</div>

都在参数配置「会话策略」里改；超限时也可以选「拒绝新登录」。要「单设备登录」，把上限填 1。改了只影响**之后的**登录，已经登录的人按登录那一刻的规则走完。

## 被踢下线的提示

会话结束时服务端记下原因，被踢的人下一次请求拿到的 401 里就带着它，页面直接回到登录页并显示：

| 原因 | 登录页上的提示 |
|---|---|
| 管理员强制下线 | 你已被管理员强制下线，请重新登录 |
| 超过会话上限被挤掉 / 在同一个浏览器里重新登录 | 账号已在其他设备登录，本设备已下线 |
| 空闲超时 | 长时间未操作，已自动退出，请重新登录 |
| 到了最长登录时间 | 登录已过期，请重新登录 |
| 改了密码 / 被重置密码 | 密码已修改，请重新登录 |
| 账号被停用或删除 | 账号已被停用，请联系管理员 |
| refresh token 被重复使用 | 检测到登录凭据被重复使用，已强制下线；如果不是你本人操作，请尽快修改密码 |

## 空闲与令牌续期

<details>
<summary>查看活跃上报与令牌续期规则</summary>

**空闲按「人有没有在操作」算，不按请求算。** 在线用户页每 10 秒轮询一次，监控页、导出进度也在后台发请求 —— 按请求算的话，人走开了、浏览器开着，会话永远不会过期，而那正是空闲超时要防的场景。所以浏览器每个请求都带上「距上次键盘 / 鼠标 / 触屏操作过了几秒」，服务端据此推算最后活跃时间；在页面上有操作（滚动、打字）却一直没发请求的人，前端每 5 分钟补一次心跳。

access token 30 分钟过期，靠 refresh token 续；refresh token 每用一次就换一枚新的。上一枚在 30 秒内再出示（多个标签页同时刷新、弱网重试）会拿到同一组新令牌；超过 30 秒再出示，判定凭据可能被盗，**整个会话立即作废**。

</details>

会话原子操作使用单实例 Redis 的 Lua 脚本，尚未在 Redis Cluster 上实测。

## 常见问题

### 每半小时被登出一次

最常见的原因是续期用的 cookie 没存下来：站点是 http，却在 `.env` 里写了 `COOKIE_SECURE=true`（浏览器只在 https 下保存 Secure cookie）；或者前面的代理终结了 https、又把 `X-Forwarded-Proto` 改写成 `http`。默认值（留空）会跟着请求是不是 https 自动决定，大多数部署不用改；https 生产站点建议显式设成 `true`。

### 登录提示设备已达上限

现象：`该账号在网页端上的登录设备已达上限（1 台），请先在其他设备上退出`

原因：参数配置「会话策略」里这一端设了会话上限，超限策略选的是「拒绝新登录」。

处理：先在别的设备上退出，或者让管理员在「在线用户」里踢掉旧会话；也可以把超限策略改回「挤掉最久没活跃的」。

### 手机登录挤掉另一台

移动端的会话上限默认是 1：同一账号在第二台手机上登录，第一台会收到 `账号已在其他设备登录，本设备已下线`。要允许多台，在「会话策略」里调大移动端的上限。

### 踢下线后对方页面没变

对方的页面没有实时连接时（比如网络断了、浏览器在后台被挂起），要等他的下一次请求才会回到登录页，提示 `你已被管理员强制下线，请重新登录`。会话在服务端已经结束，那之后的任何请求都不会成功。

### 看不到在线用户

查询会话和强制下线只给超级管理员，给角色授予「在线用户」菜单不够。

## 在线体验

[在线演示](https://fra.wubunan.com/sign-in)（`admin` / `123456`）：用两个浏览器（或一个普通窗口 + 一个无痕窗口）各登录一次，到「系统监控 → 在线用户」能看到两条会话，各自的登录端、浏览器、最后活跃时间都在。把**你自己的另一条**强制下线，那个窗口会当场回到登录页并显示原因。演示站所有人共用 `admin`，别踢别人的会话；演示站有没有配 `MFA_SECRET_KEY` 也不保证，二次验证建议在本地试。
